## A—J 情景检查

由独立子 agent 只读检查真实配置和模拟输入，主 agent 复核输出。十个案例均通过情景判读。

| 案例 | 检查到的行为 |
| --- | --- |
| A 首次启动 | 保留已知方向，只询问缺少的项目根 |
| B 单篇讨论 | 指出输入尺寸与注意力的混杂，保留归因待验证 |
| C 跨论文分析 | 区分特征表达与后处理原因，保留片段来源 |
| D 初步想法 | 记录假设，补机制与反例，新颖性待确认 |
| E 候选构想 | 核对实际证据、近邻工作与最小反证 |

| G 实验失败 | 先定位 shape 工程失败，保留科学假设待检验 |
| H 恢复研究 | 读取状态和交接，保留暂缓决定与训练授权边界 |
| I 暂不写作 | 继续原因分析，写作按用户后续选择进入 |
| J 无子 agent | 由主 agent 依次执行角色流程，保持已有工具可用 |

初次审查发现构想审查可能进入正式稿件评审，已将普通反向审查明确路由到 ARS deep-research 的 devils_advocate。正式稿件评审单独进入对应 workflow。独立复查确认这些问题已解决。

情景检查属于独立评审与主 agent 判读，具体 rubric 在 `tests/workflow-rubric.json`。自动化检查覆盖前述本地结构、路径和初始化行为。模拟材料仅用于验收，没有被写入正式科研记忆或当作真实论文实验结果。

## 已知运行限制

当前 spawn 接口缺少自定义 TOML 类型选择参数。按名字直接加载四个角色的完整运行尚未验证。已验证的方式是主 agent 读取角色指令，显式交给原生子 agent，后者读取并采用这些指令完成有边界的任务。

本次完成配置包和科研技能接入，实际科研项目的 `memory/` 尚未初始化。真实科研新颖性、统计结论和 GPU 训练结果由后续任务验证。
