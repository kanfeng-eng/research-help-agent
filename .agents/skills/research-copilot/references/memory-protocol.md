# 项目科研记忆

## 根目录与首次初始化

科研记忆位于用户当前指定的科研项目 `<project>/memory/`。配置包、技能目录与实际科研项目分别定位，项目可与配置包放在不同位置。无法确定根目录时只询问这一个必要信息。

首次进入已明确的实际科研项目时，自动检查并执行以下命令补齐最小记忆，脚本位置相对本 skill。已有项目根和当前授权直接沿用。配置包维护任务保持构建模式。用户明确要求临时讨论、不保存或只读时，按本轮范围处理。

```powershell
python scripts/init_memory.py --project-root "<科研项目绝对路径>"
```

脚本只补充 `memory/README.md`、`00_Current_State.md`、`08_Research_Handoff.md`，已有文件保留。研究方向、论文与实验记录在实际产生内容时创建。使用绝对路径参数，避免把记忆初始化到技能安装目录。首次使用可直接按模板维护文件，Python 暂不可用时说明采用的方式。

## 每次读写

启动先读索引、当前状态及交接，再有选择地读取相关记录。明确项目内默认自动保存有价值的新信息，包括准确的论文梳理、讨论中的纠正、新观察、假设、反例、检索结论、实验结果和研究员决定。仅限定“用给定材料”影响证据范围，记忆仍按项目默认规则维护。

用户未提出想法、论文暂无线索、一次讨论很短，都可以产生需要保存的准确理解。按来源、问题或实验 ID 检查已有记录，补充真正的增量。保存后核对实际文件，向用户简述更新位置。纯重复内容可以沿用原记录，研究状态发生实质变化时同步状态和交接。

按 [自动研究编排](research-orchestration.md) 保存方向版本、当前方案、瓶颈问题 ID 与证据、谱系状态、核心分析状态、上次实际处理的证据范围及待继续动作。瓶颈关联到现有问题、论文与实验记录，附适用条件、来源和支持/削弱/待核查状态，原因解释随新证据保留修订历史。进入新会话时据此恢复，材料重复时沿用既有分析，方向或证据变化时更新受影响部分。

只有用户明确指定临时讨论、不保存或只读，才采用对应例外。项目尚未确定时先分析可用材料，持久化前确认科研根目录，期间如实说明保存状态。代码、数据、权重、大日志使用原项目目录，记忆记录路径、版本和摘要。

主 agent 统一写正式记忆。子 agent 默认返回可审查结果，修改实验代码时使用单独授权的写入范围。对正式记忆的改动先重新读取当前文件，检查是否有用户修改或同时更新。原结论被修正时追加日期、原因、证据与取代关系，保留负面结果、排除的 IDEA 和决定过程。

模板位于 `../templates/`。索引使用稳定 ID 和相对项目路径，源材料移动时更新对应定位。缺文件、过期运行记录或未知事实进入待核查项，避免补造历史。

ARS 各 workflow 的阶段记录位置按 [科研能力路由](research-providers.md) 中的路径映射执行。主 agent 在委派前提供实际绝对输出路径，回收后将结论关联到正式索引和状态。

这里的项目 `memory/` 与 Codex 主机全局记忆为独立系统。初始化或维护项目记忆时，写入范围限定在明确的科研项目。
