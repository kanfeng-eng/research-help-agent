# 专业角色协作

## 原生加载

本包的 `.codex/agents/*.toml` 是项目级原生角色文件，包含 `name`、`description` 和 `developer_instructions`，模型及推理强度继承当前主会话。角色说明中的只读约束属于行为指令，实际权限仍跟随父会话。

在以本包为项目工作目录的新会话中按角色名称委派。当前会话若没有重新加载角色，不能把普通子 agent 说成已按自定义类型加载。可将该角色的实际指令及任务交给当前可用的原生 subagent，并明确这一执行方式。

本次桌面运行时的 smoke test 显示 spawn 工具没有自定义角色选择字段。遇到同一接口时，主 agent 读取对应 TOML 的 developer_instructions，将其连同上述输入合同作为原生 subagent 的任务上下文传入。保持模型和权限继承，记录“原生子 agent，角色指令显式传入”。该方式实现职责分工，自定义 TOML 类型直接加载的状态仍单独记录。

## 输入合同

每次委派提供当前方向与目标约束、baseline/方案、相关瓶颈及证据、任务目标、明确的科研项目根、相关论文/记忆/配置/日志、未知项、已有资源授权、允许写入的路径、预期结果和完成条件。角色默认只读取必要材料。实验工程师只有在任务明确授权时修改或运行对应代码。

## 返回合同

返回任务与检查范围、实际读取/检索/执行的内容、带来源的发现、证据类型、推理与竞争解释、未核实事项、产物/日志路径、执行状态和建议。检查的源文件路径和内容定位应可由主 agent 复核。

## 何时分工

- 文献分析员检索、核对原文及近邻工作。
- 创新审查员独立找反例、简化解释和机制对照。
- 实验工程师实现并验证已确认方案，保存真实执行轨迹。
- 结果分析员独立核对配置、日志、比较条件和结果解释。

独立检索或独立结果复核可以并行，依赖同一产物的步骤按顺序执行。存在写入时划分互不冲突的文件范围。主 agent 可以在等待期间完成其他有用工作，收到结果后核对证据，再维护正式记忆。结论冲突时展示双方依据与可区分的测试。

## 后备执行

原生工具或自定义角色不可用时，由主 agent 按同样职责先后执行相关分析，记录“主 agent 角色模式”。科研讨论、文献核查、实验设计与项目记忆仍可继续。实际独立复核的程度按真实执行方式说明。
