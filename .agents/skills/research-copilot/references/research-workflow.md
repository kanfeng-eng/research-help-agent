# 研究讨论与双向探索

## 启动与恢复

已有项目优先读记忆和已有资料。只确认影响当前研究的方向、用户想法、进展、问题和资源。缺信息时一次问最重要的一项。新项目可保持宽方向，用户可跳过未知项。

从 `memory/08_Research_Handoff.md` 追到对应论文、IDEA 和实验文件，检查文件、配置及运行状态是否仍存在。交接中的运行记录需要结合实际日志验证。

随后按 [自动研究编排](research-orchestration.md) 判断并执行本轮动作。方向明确后自动建立或更新谱系；已有材料达到问题与机制的分析条件时直接运行核心逻辑。谱系追踪、论文讨论、跨论文分析和反证设计可以往返。

## 方向导向的论文讨论

默认以科研合作者的方式围绕当前 Research Direction 探讨创新、方法改进和瓶颈。用户说“看这篇”“从这篇开始”“读完了”或只提供论文时，先自主查阅实际材料，带着项目问题分析。用户已有理解或想法时，把它们纳入讨论并核对逻辑。

### 先恢复当前研究问题

从本轮请求、`01_Research_Direction.md`、当前状态及相关实验中提取任务/场景、目标指标、资源约束、现有 baseline/方案、当前卡点及其证据。沿用已知内容，用当前请求和新证据核对历史判断。宽方向可以先分析主要矛盾，baseline 未知时将实现建议写成条件化方案，具体迁移依赖的接口保留待查。方向确实缺失且影响判断时，只问最重要的一项，同时给出材料已经支持的分析。

方向已知而瓶颈尚未定位时，从论文假设、失效条件和目标约束中提出值得核查的问题及诊断依据。研究机会可以先处于开放问题或原因假设阶段，随讨论和证据积累发展。

方向、瓶颈解释与具体方案分别记录。用户提出的模块或旧 IDEA 保留其成熟度，研究目标依据研究员的实际表述确定。用户明确改变方向后，以新目标更新受影响的谱系和问题，历史记录保留变更原因。

### 形成对当前方向有用的推理

- **关联目标和瓶颈。** 先说明论文对当前方向的哪项问题有帮助，或只能提供哪类间接启示。瓶颈表述附失败样本、诊断、日志或论文位置，区分已观察现象、原因假设和在特定条件下已排除的解释。单篇论文的结果用于启发项目诊断，实际项目瓶颈由本项目证据判断。
- **拆开原机制与迁移假设。** 核实作者解决的问题、因果解释、必要条件、关键公式/信息流和支持证据，再说明该机制为什么可能作用于当前瓶颈。迁移涉及数据、尺度、任务、训练、评价或硬件差异时逐项说明影响，AI 提案标为待验证。
- **落到现有方法。** 改进建议定位到当前流程的具体环节，说明保留、替换或新增什么，作用路径及时间、计算、内存等代价。用户约束涉及端到端效率时计入相关额外开销。同时比较更简单的可行做法和最接近工作，创新措辞遵循真实检索范围。
- **用诊断处理卡点。** 已有尝试卡住时先结合实际记录判断工程、比较条件和科学假设，回看哪条预期未成立及其竞争解释。优先提出能区分原因的低成本诊断，再据结果选择机制或调整方法。给出支持、削弱及不足以判断的结果含义。
- **形成下一项研究判断。** 连接“方向目标 → 现象与原因假设 → 论文机制 → 对现有方案的改进 → 可观察预测 → 最小对照”，说明它可能推进目标的理由和当前证据强度。没有可靠机会时保留论文逻辑、已排除的解释和与方向相关的待核查问题。

这些维度用于内部分析，回复按当前最重要的研究判断展开，证据与推理相连。首轮给出具体分析和最有价值的验证或讨论点，细节随用户追问展开。一般追问围绕能改变判断的证据、机制或实验选择。

### 原文与记录

核对标题、作者、年份、版本和原文范围。围绕当前研究方向，检查论文的关键假设、证据缺口、失效条件、近邻工作与可检验的机制。公式、维度、数据流和实现细节按其对研究判断的影响展开。作者公开论证与真实发现时间线分别按已披露证据记录。

有值得讨论的机会时，具体说明它来自哪项证据、为什么当前方案可能不足、有哪些替代解释、怎样用最低成本实验反驳。用户和 AI 可以围绕这些判断往返讨论，逐步收敛。

暂时找不到有依据的机会时，给出有内容的论文梳理，串起研究问题、作者原因解释、解决机制、关键公式/信息流、实验论证和边界，并说明与当前项目的联系。结论使用“在已检查材料中暂未形成有依据的研究线索”等范围化表达。

阅读路线、阅读任务表、理解检查题和“读完再回答”的节奏仅用于明确的带读请求。创新讨论中的追问围绕证据、机制、反例和实验选择展开。用户明确要求自主精读或笔记时按该请求的范围与格式完成。

按需要创建 `memory/papers/Paper_<ID>.md`，使用 [论文记录模板](../templates/paper-note.md)。记录论文与方向、瓶颈及现有方案的关系，用户实际的理解和判断与 AI 建议分别标记。跨论文机制和瓶颈进展链接现有 `04_Cross_Paper_Analysis.md`、`05_Research_Gaps.md` 或 `07_Open_Questions.md`，沿用问题 ID。已有 HTML 精读笔记可以作为带来源的索引，核心论文事实回到原文核实。

## 论文驱动

从方法假设、实验条件与局限出发，检查它们能解释或缓解当前方向中的什么问题，包括信息损失、冗余、模块冲突或失效场景。把作者承认的局限、有证据的额外局限和待测想法区分开。用户明确要求改进论文本身时按该范围开展。读后没有新问题时，保存本次理解即可。

## 问题驱动

从领域现象、任务需求或部署约束出发，确定问题发生的位置、可能根因及现有路线。让问题决定需要检索的论文，再比较机制与条件。关注共同根因、论文解释的矛盾、互补方法和约束变化带来的新现象。

## 跨论文分析

相同指标名需要核对定义、数据划分、输入、骨干、训练预算及测量硬件。每个综合判断链接到相关论文或实验。按“问题—机制—条件—证据”建对照，重复观察可合并，来源和变化历史保留。更新 `04_Cross_Paper_Analysis.md` 和确有新增内容的开放问题记录。

每次有实质新证据时检查 [核心分析触发条件](research-orchestration.md)。达到条件就在当前范围内执行，已完成的综合按实际输入记录复用。论文讨论结束后留下待验证问题时，记录下一项应核查的材料或对照及其理由。

## 可选写作

用户明确进入写作后，先逐项核查下面的研究依据。每项记录“已具备／待补充／不适用”、实际来源位置及理由，待补项给出下一步。理论、综述、数据集或方法研究按论文类型判断相关证据，实验检查的不适用项需说明原因。

| 核查项 | 需要定位的材料 |
| --- | --- |
| 研究问题清晰 | 问题、场景、范围和要解释的现象 |
| 相关工作充分 | 有日期与范围的检索、最接近工作及其机制比较 |
| 方法明确 | 核心机制、假设、公式/信息流与实际实现或理论构造 |
| 关键实验真实完成 | 对应 run、实际配置、终止状态、日志和结果；理论工作对应推导与证明 |
| baseline、对照和必要消融 | 公平比较、控制变量及机制区分证据 |
| 结果支持研究主张 | 每项主张与相应数据、统计不确定性或证明的对应关系 |
| 方法为何有效 | 机制分析、反例与竞争解释的检查 |
| 可复现性 | 数据/split、代码版本、配置、种子和环境，或可复查的理论推导/综述检索过程 |
| 创新性措辞有依据 | 已确认的差异、检索边界与仍待核实的内容 |

将核查结果保存在 `memory/Writing_Readiness.md`，链接已有论文、IDEA、实验与决策。全部满足相关条件时进入相应稿件写作；存在缺口时先给出其影响和补证计划，当前正文范围限定在已有依据支持的内容。用户明确要求研究计划、大纲、方法片段或带待验证项的草稿时，按该具体范围完成，并保留结果和新颖性的真实状态。

核查只组织已有证据，实施新实验跟随实际授权。研究可以长期停留在问题探索与实验循环，后续根据证据和研究员决策推进。
