# 自动研究编排

本规范将 trace the lineage 与 run the core logic 实现为本地主 agent 的研究动作，复用已安装的 ARS 方法。它们是本 skill 的阶段名称。开始前先判断本轮是否是实际科研、用户限定的讨论或配置包维护，沿用当前权限和任务范围。

## 每轮检查与执行

读取方向、文献索引、跨论文分析、研究问题和已有交接，检查以下触发条件。有足够上下文时在当前会话直接开展对应工作，汇报已查到的证据及产物。完整处理后再将动作标为完成。若范围或工具受限，完成可做的部分，保留具体缺口与恢复入口。

| 事件 | 当前应执行的动作 |
| --- | --- |
| 已有研究方向，尚无可用谱系 | 自动完成范围内的初步谱系追踪 |
| 方向、关键约束或任务目标发生实质变化 | 更新受影响的谱系分支与问题对照，保留原方向和变化原因 |
| 新论文、观察、失败或反例改变了已有联系 | 评估其影响，更新相关谱系并按下面条件运行核心分析 |
| 证据已支持一个明确问题及可比较的机制，核心分析尚未覆盖这些输入 | 自动运行该问题的核心分析 |
| 新证据推翻旧解释、实验暴露异常或研究停滞 | 回看竞争解释和对应分支，定向补证并重新综合 |
| 恢复会话 | 核对上次实际完成状态和剩余动作，继续已授权的未完成部分 |
| 输入只是重复已分析材料 | 沿用已有分析，说明引用位置，处理本轮新增问题 |

用户明确只讨论一个局部问题时，先完成这个问题，按其证据需要局部追踪。明确只用给定资料时在现有证据内工作。明确只读或不保存时返回分析与实际处理范围。维护配置包时进行配置实现和验收。

## Trace the lineage

### 何时开始

知道研究员的方向后就检查并追踪。方向暂时宽泛时形成粗粒度初图，给出检索边界和需要澄清的关键轴。已有谱系时先复用并核对受影响部分。

### 实际工作

1. 从当前任务、场景、目标和资源约束提取检索词及同义问题表述，记录本轮范围和日期。
2. 使用 ARS deep-research 的文献检索、来源核查与综合方法，定位奠基工作、重要分支、机制转折、最接近方案及反对证据。利用参考文献和后续引用追溯关键关系。
3. 优先核查决定路线划分的原始论文。摘要、完整原文和二手综述分别记录实际阅读范围，无法访问的材料保留待查。
4. 解释每条关系，前作处理什么瓶颈，后作继承、替换、反驳或放宽了什么假设，哪些问题仍然存在。仅有引用关系或时间先后时，机制继承关系保持待核实。
5. 对照数据、评价、训练/推理输入及资源预算。条件不同的数值保留各自范围，当前目标约束对路线选择的影响单独说明。

### 有用产物与停止条件

将谱系保存到 `memory/Research_Lineage.md`，节点链接论文记录，关键边附来源位置、证据身份和未解决问题。可以采用紧凑的分支表与关系清单。完成本轮主要分支的初步定位、关键关系核查和剩余缺口记录后返回讨论。尚不完整时标为 partial，并确定下一项最有价值的补证。

需要继续阅读的文献按解决哪项不确定性排序，记录为 AI 的核查任务。用户明确要求阅读建议时再输出其阅读安排。路线图和来源可以随新证据迭代，当前方向与资源决定检索范围。

## Run the core logic

用户在本项目中将它定义为跨论文综合、机制推理、反例审查与最小实验设计。

### 触发条件

材料应能支撑一个明确研究问题，以及至少一个可讨论的机制或竞争解释，并且相对上次综合有实质新信息。例如，不同方法对同一现象给出不同解释、同一失败在多个条件下重现、理论与实验矛盾，或新增诊断足以检验一个假设。

不设置固定论文数量门槛。多篇重复材料可能没有新信息，一篇带有关键诊断或反例的论文也可能触发针对性分析。证据不足时先准确整理论文，记录开放问题并定向补证，说明尚未满足的条件。

### 完整分析动作

1. **锁定问题与证据。** 从谱系、论文和实际观察提取具体场景、现象、评价口径及来源，区分作者报告和推断。
2. **跨论文比较。** 对齐各方法的假设、机制、输入输出、实验条件和成本，找共同根因、互补关系、冲突和未覆盖条件。
3. **机制推理。** 形成原因解释与竞争解释，必要时展开公式、信息流或复杂度，指出哪些环节已有证据、哪些仍是猜想。
4. **近邻与反向审查。** 调用文献核查和创新审查职责，检查相同机制、已有反例、简单替代、参数/算力/训练混杂，以及研究空白是否只由搜索不足造成。
5. **最小可区分实验。** 给出能区分机制与竞争解释的 baseline、变量、对照、指标、预算假设、支持/反驳/不确定标准。缺关键条件时保留条件化方案和具体待补项。
6. **形成判断并回到讨论。** 可以留下观察、开放问题、待证假设、候选研究空白、成熟构想或有证据的否定。给出当前最值得讨论的判断和原因，研究员决定方向及实际资源投入。

有价值的机制得到阶段性支持后，可以进一步查条件边界或迁移范围。分析暂无线索时整理已知结论、排除的解释和未解问题。提出的实验计划进入相应记忆，真实执行按既有实验授权与预算处理。

核心分析的完成状态与假设的验证状态分别记录。六项分析动作在本轮范围内完成后可记为 completed，假设仍可保持 Hypothesis；实验执行结果随后另行记录。缺少近邻核查或机制依据等必要动作时才保留具体 partial 项，下一轮从该项恢复。

## 状态、增量与交接

在 `memory/00_Current_State.md` 和交接中按需维护以下研究字段。它们是项目记录内容。

- 当前方向与约束版本，以及变更原因。
- 谱系状态 `not-started / partial / current / needs-update`，实际核查范围、来源和缺口。
- 核心分析状态 `not-ready / ready / partial / completed`，触发原因及完成/缺失环节。
- 上次综合实际使用的论文 ID 与版本、观察/假设/实验 ID、结论和产物位置。
- 相对上次综合的实质变化，待继续的动作、原因、完成条件和已知资源范围。

同一批证据和同一问题沿用已有产物，新增内容只更新受影响的部分。仅改写措辞或重复已知结论不计为新的核心分析。已有文献库达到条件时可立即运行，用户提出不同任务或限制时按本轮范围重排。

谱系进入 `memory/Research_Lineage.md`，核心分析进入 `memory/04_Cross_Paper_Analysis.md` 并链接相应问题、IDEA 和实验计划。保留每次实质更新的日期、输入范围和理由。跨会话续接依赖这些记录，实际后台运行能力及权限按当前环境核查。
