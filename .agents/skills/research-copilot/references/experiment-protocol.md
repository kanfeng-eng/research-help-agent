# 从假设到结果

## 最小实验

先确定核心假设与可观测预测，再选能够区分机制的最低成本对照。实验计划按 [模板](../templates/experiment-plan.md) 包含目的、预测、baseline、数据及划分、预处理、实验/控制变量、对照、指标、依赖、资源预算、步骤、支持/失败/不确定标准与混杂风险。

资源在方案选择时进入约束。预算包含设备、GPU/CPU 时间、峰值内存、存储及允许的重试范围。已经有明确授权时照此执行，新预算或外部资源需要补充授权。模型、数据或依赖下载按实际体积和已有授权判断。

无人机小目标检测按任务核对忽略区域、类别映射、每图框上限、AP 实现、尺寸统计坐标、原图/序列级划分。比较输入尺寸、训练数据、骨干、增强、参数量、计算量与端到端计时，随实际假设选择必要控制项。

## 工程实现

先读现有入口、代码和配置，复用其数据流与表示。只修改实验涉及的文件和变量，必要时验证 shape、数值、梯度和边界。根据可运行依赖进行轻量 smoke test，再进入已确认范围的正式运行。

实现与修复保持用户已有授权。上游示例只执行手写命令等默认限制不能替代本次明确的实现任务。recoverable failure 在同一方案与预算内诊断修复，改变机制、数据权限或成本后重新交还用户判断。

## 真实执行记录

每个 run 使用唯一 ID。执行前记录当前代码版本；非 Git 项目保存涉及源文件的 SHA-256 和配置副本。记录数据版本/split、种子、环境、依赖、命令、工作目录、预算、输出位置和实际进程状态。沿用项目已有实验管理工具，当前任务没有必要时使用本地配置和日志。

状态使用 `planned`、`code-ready`、`smoke-tested`、`running`、`failed`、`completed`、`analyzed`。进程启动、GPU 忙碌、代码通过检查和实验完成各自对应不同证据。完成时核对终止状态、日志、指标与产物，再判定实验是否完整。

失败保留原日志与配置，修复后的重试使用新 run ID，并说明变化。恢复实验前核对已有检查点、真实进度和评测入口。会话期间需要等待的任务持续检查到请求的完成条件，跨会话状态依赖真实进程和记忆交接。

## 分析顺序

1. 工程正确性。核对数据、标签、实现、梯度、收敛、实际参数与计划。
2. 实验有效性。核对 baseline、划分、泄漏、控制变量、指标、规模、随机波动和混杂因素。
3. 科学解释。比较预先预测、竞争解释和反例，指出结果支持、削弱或不足以判断哪项假设。

按需求添加重复种子、消融、跨数据或鲁棒性验证。指标改善需同时说明绝对变化、比较分母、方差与成本，单次提升的结论范围跟随已有证据。实现有误导致的失败先记录为工程结果，不能直接用于反驳科学假设。

结果分析使用 [实验记录模板](../templates/experiment-log.md)，研究选择使用 [决策模板](../templates/decision-record.md)。继续、调整、补充验证、暂缓、放弃或转向的建议附依据，正式选择保留研究员原意。
